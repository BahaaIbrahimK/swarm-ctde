found that 3 of those "fixes" were never connected to the training path**, plus
4 further defects. All 13 are now fixed and verified on the real runtime path.

**Consequence:** every result produced before this date is
**invalid-for-inference** and marked as such.

## Why this audit mattered

An external reviewer read the implementation and found five problems that the
existing 51-test suite had missed. They were not missed by bad luck. **Each test
exercised its component in a way that bypassed the failure.**

That pattern is the real finding, and it is worth stating plainly:

> Confident comments and passing tests were written around assumptions that had
> never been verified end-to-end.

Two examples:

| Test | What it did | What it missed |
|---|---|---|
| `test_gae_terminal_cuts_bootstrap` | Put the terminal on the **last** buffer element | That is the one index where the off-by-one is invisible — the last step reads `last_dones` instead of `dones[t+1]` |
| `check_survival_incentive` | Set `env._crashed = True` by hand, then called `_computeReward()` | Tested the reward **formula** while bypassing the call **order** that made it dead code |

The new suite (`tests/test_correctness.py`) follows one rule:

> **Test through the public path the experiment actually uses.**
> Never poke a private flag to reach a state the system should reach on its own.
> If reaching it naturally is hard, that difficulty is information.

## Defect 1 — GAE terminal off-by-one

**Severity: invalidates results.**

A transition is stored as `(s_t, a_t, r_t, s_{t+1}, done_t)`, so `dones[t]`
answers *"did the episode end as a result of transition t?"*. The bootstrap for
`t` must therefore read `dones[t]`.

The code read `dones[t+1]`, shifting every mask one step.

**Measured**, with a terminal at t=1 in a 3-step rollout:

```
step   correct    actual
t=0    +1.46525   +0.50000     WRONG
t=1    +0.50000   +1.93080     WRONG
t=2    +0.99500   +0.99500
```

**Fixed:** `compute_gae` now reads `self.dones[t]`.
**Guarded by:** `test_gae_terminal_MID_rollout`.

## Defect 2 — GAE crossed episode resets

**Severity: invalidates results.**

Two masks are required, and they are not the same:

| Mask | From | Effect |
|---|---|---|
| **bootstrap** | termination only | a terminal state has no future — exclude `V(s_{t+1})` |
| **boundary** | termination **or truncation** | the next stored transition is a different episode — stop the recursion |

Time-limit truncation is the subtle case: the future still exists, so we *do*
bootstrap — but off the episode's **true final state**, not `values[t+1]`, which
belongs to the reset episode.

The trainer stored only `terminated`. On truncation it wrote `done=0`, the
environment reset, and the recursion ran straight through into an unrelated
trajectory.

**Fixed:**
- `RolloutBuffer` stores `truncations` and `truncation_values`
- the trainer captures `V(s_final)` **before** the reset
- the recursion uses separate bootstrap and continuation masks

**Guarded by:** `test_gae_does_not_cross_truncation_boundary`,
`test_gae_normal_rollout_unchanged`.

## Defect 3 — The crash penalty was dead code

**Severity: invalidates results. The most embarrassing of the five.**

`BaseAviary.step()` calls:

```
line 377   reward     = self._computeReward()
line 378   terminated = self._computeTerminated()
```

`_computeTerminated()` was what set `self._crashed`. So on the crashing step the
reward was computed while the flag was still `False`, the episode then ended,
and the penalty was never delivered.

**Measured** on a real dive-to-crash episode:

```
ended at step 60: terminated=True crashed=True
reward on FINAL step  = +0.88
reward on step before = +0.88      ← identical
crash_penalty configured = 50.0    ← never applied
```

This matters beyond bookkeeping: the penalty exists to guarantee return is
monotone in survival time, which is the property that killed task version v1.
**That guarantee did not hold.**

**Fixed:** a pure `_check_failure()` returning `(failed, reason)` without
mutating state. Both `_computeReward()` and `_computeTerminated()` call it, so
the verdict is order-independent.

**Guarded by:** `test_crash_penalty_delivered_by_real_step`,
`test_crashing_early_is_worse_than_flying_badly` — both driving real crashes
through `env.step()`.

## Defect 4 — Collisions were never detected

**Severity: safety metric was wrong.**

The charter lists collision as a termination condition. The implementation
checked floor contact, tilt, and distance from the reference — **not
inter-drone separation**. Two drones could occupy the same space with nothing
recorded, and `crash_rate` was reported as though it measured collisions.

**Fixed:** pairwise separation check at `COLLISION_RADIUS_M = 0.15`
(a CF2.x is ~92 mm across; 0.15 m also captures the near-miss regime where a
real flight test would be aborted). `info` now carries `failure_reason`,
`collision`, and `min_separation_m`.

**A property discovered while testing this:** collision is **physically
unreachable by policy action** at valid spacings. With `max_offset_m = 0.2`,
two drones can close at most 0.4 m, so a 1.0 m formation bottoms out at 0.789 m.

That is a genuine safety property of the action clamp, and it is now asserted
rather than left implicit — if a future change raises `max_offset_m`, the test
fails and forces an explicit decision.

**Guarded by:** `test_collision_is_detected_when_it_occurs` (tests the
detector, by placing drones in contact through PyBullet's own API) and
`test_collision_unreachable_by_policy_action_at_valid_spacings`.

## Defect 5 — The privileged critic was not privileged

**Severity: invalidates the `k3+P` rung.**

`get_global_state()` exposed only `wind_vec` — the **steady mean** wind. The
stochastic OU gust, which constitutes essentially the entire disturbance, was
withheld.

**Measured** at `gust_std_ms = 4.0` after 50 steps:

```
wind_vec (given to critic)   [ 0.37,  0.87,  0.10]
gusts    (withheld)          [-1.30, -10.37,  3.09]  ...
```

The rung labelled *maximal centralization* was missing the dominant term.

**Fixed:** `get_global_state()` now returns `gusts` (per-drone) and
`air_velocity` (mean + gust — exactly what the drag force is computed from).
The privileged block of the critic input carries `air_velocity`.

**Guarded by:** `test_privileged_state_contains_the_actual_disturbance`.

## Defect 6 — Critic capacity was not exactly constant

**Severity: confounds the ascending side of the interior optimum.**

The fixed-width projection did not make parameter counts equal, because the
projection's **input** still grew with `k`:

| Rung | Input | Projection params | Total |
|---|---|---|---|
| k0 | 12 | 832 | 83,521 |
| k3+P | 33 | 2,176 | 84,865 |

The old defence was that the spread *favours high k*, so it cannot explain a
decline at high `k`. **That argument is only half right.** It does not explain
away `k1` beating `k0` — the ascending side of the claimed interior optimum,
which is exactly the part the paper needs.

**Fixed:** every critic now takes a **padded fixed-width input** (33-D for
N=4) with excluded teammate slots **zeroed**. The network is literally the same
object at every rung; only the information content of its input changes.

**Guarded by:** `test_critic_parameter_count_is_EXACTLY_equal_across_rungs`,
`test_masked_input_zeroes_excluded_teammates`.

## Defect 7 — The actor could not compute the gap derivative

**Severity: an alternative explanation for the entire pilot result.**

The actor received relative **position** to its predecessor, but its own
**absolute** velocity. Being memoryless, it could not compute `d(gap)/dt`.

The `k=1` critic received relative velocity **directly**.

**Measured**, drone 2 at step 30:

```
actor own velocity        [ 0.0385, -0.0197, -0.0699]
relative velocity         [ 0.0561, -0.0119,  0.0943]   <- not available to actor
k=1 critic slot [15:18]   [ 0.0561, -0.0119,  0.0943]   <- available to critic
```

So `k=1`'s measured advantage may have been *"the critic has a derivative the
actor lacks"* rather than *"the critic sees aerodynamic coupling"*. That is a
competing explanation for the whole result, and it had to be removed.

**Fixed:** the actor now observes velocity **relative to its reference**. A real
follower with UWB or vision can estimate this, so withholding it was not
realistic either.

**Guarded by:** `test_actor_can_compute_the_gap_derivative`.

## Defect 8 — Leader and follower observations were aliased

**Severity: role confusion under a shared actor.**

The two observations MEAN different things:

| Agent | `obs[0:3]` | `obs[6:9]` |
|---|---|---|
| Leader | absolute mission-tracking error | velocity vs commanded trajectory |
| Follower | gap to the drone above | velocity relative to that drone |

With a shared actor and **no role indicator**, the network could not tell which
regime it was in. The old code comment claiming agents "differ only by formation
slot" was wrong: the leader has exogenous mission dynamics, followers have
predecessor-dependent references.

**Fixed:** observation is now 13-D, with `obs[12]` a role flag (1 = leader,
0 = follower).

**Guarded by:** `test_leader_observation_is_mission_relative`.

# Second review — 16 September 2026 (later the same day)

## Defect 9 — Padded critic inputs were never wired into MAPPO

**Measured on real learners, before the fix:**

```
rung    critic_obs_dim   critic params
k0      13               83,585
k1      19               83,969
k3+P    34               84,929        spread: 1,344
```

`MAPPO.__init__` called `critic_input_dim(level)` (rung-dependent) and both
`act()` and `compute_values()` called `build_critic_input(...)` **without**
`padded=True`.

**Fixed:** `max_critic_input_dim()` in the constructor; `padded=True` in both
call sites. Verified: all rungs now 34-D, 84,929 params.

**Guarded by:** `test_real_mappo_critics_have_identical_input_width`,
`test_real_mappo_critics_have_identical_parameter_count`,
`test_real_act_returns_fixed_width_critic_input` — all instantiating real
`MAPPO` objects.

## Defect 10 — The privileged critic still consumed the steady mean

**Measured from a real `act()` call:**

```
air_velocity (intended)   [-0.933, -9.504,  3.199]
critic received           [ 0.366,  0.869,  0.105]   ← steady mean
```

**Fixed** by the padded path, which reads `air_velocity`.
**Guarded by:** `test_privileged_rung_critic_actually_receives_the_disturbance`,
`test_non_privileged_rungs_get_no_disturbance_information`.

## Defect 11 — Wind acted on 1 of 5 physics substeps

`_apply_wind()` was called from `_preprocessAction()`, which runs **once per
control step**. `BaseAviary` then executes `PYB_STEPS_PER_CTRL` substeps, and
PyBullet **clears external forces after each**.

**Measured:** 1 call per `env.step()`, 5 substeps → **20% of the intended
impulse**, and the disturbance silently scaled with `ctrl_freq`.

**Fixed:** the OU gust advances once per control step (`_advance_gusts()`); the
force it implies is applied every substep by overriding `_physics()`.

**Verified** — lateral drift over 1 s of 8 m/s wind:

```
ctrl_freq= 48   0.14715 m
ctrl_freq=120   0.14136 m
ctrl_freq=240   0.14141 m      → agree within 4%
```

**Guarded by:** `test_wind_is_applied_on_every_physics_substep`,
`test_wind_impulse_is_control_frequency_invariant`.

> A first version of the invariance test **hand-rolled the physics loop** and
> reported a false failure — bypassing the very integration path it was meant to
> validate. Rewritten to use `env.step()`.

## Defect 12 — Unbounded policy under action clipping

The policy sampled from an unbounded Normal; PPO stored that action's
log-probability; the environment then clipped to [-1, 1]. Whenever clipping
occurred, `a_executed ≠ a_in_the_likelihood_ratio`, biasing the objective.

**Fixed:** tanh-squashed Gaussian with the change-of-variables correction.
Actions are bounded by construction.

**Note:** the entropy uses the base Gaussian's entropy as a surrogate — the
squashed entropy has no closed form. Documented in the class so the
approximation is not mistaken for exactness.

**Guarded by:** `test_policy_actions_are_bounded`,
`test_bounded_policy_log_prob_is_finite_and_correct_shape`.

## Defect 13 — Crash penalty two orders of magnitude too large

**Measured:** a crash at step 60 cost **−58,790** against a normal return of
~650. The old formula scaled by the worst-case per-step return at the 3 m
termination boundary — a state a working policy never occupies.

With no value normalisation, a single failure could dominate the critic's
targets. **This is a plausible cause of the v3 late-training collapses** I had
attributed to `lr_critic`.

**Fixed:** the penalty now forfeits the remaining survival bonus plus a fixed
margin. That is all monotonicity requires.

```
crash at step  60 →   710   (1.1× normal return, was 90×)
crash at step 700 →    70

Monotonicity holds:
  crash @  60 → return  −650
  crash @ 700 → return  +630
  survive     → return  +720
```

**Also added:** `RunningMeanStd` value normalisation. Without it, critic
accuracy would be confounded with the experimental condition — since returns
scale with formation spacing and gust strength, both of which we sweep.

## The lesson, restated

The first round's mistake was testing **components in isolation** when the
defect lived in **wiring**. Three fixes were real, correct, and unreachable.

`tests/test_wiring.py` exists specifically to close that gap, and its header
states the rule: *instantiate the real objects the experiment uses*. If a
property cannot be checked that way, the code is wrong — not the test.

# Third round — reporting defects

The first two rounds fixed defects that would produce **wrong physics** or
**wrong learning**. This round fixes four that produce **wrong reporting**: the
simulation and the learner are correct, but the number that reaches the paper
is not the number we claim it is. For a journal submission these are equally
fatal and considerably harder to spot, because nothing crashes and every value
looks plausible.

## R1 — `aggregate_by_rung` pooled across formation spacings

**Severity: would have silently corrupted Claim 2.**

Formation spacing is Claim 2's *independent variable*: the claim is that the
best rung k\* tracks coupling strength, and spacing is how coupling is varied.
The aggregator grouped by rung only, with no spacing filter — so a rung's seeds
at 0.7 m and 2.5 m were averaged together.

That averages across the very axis the claim is about. A real effect would be
flattened toward its mean and reported as "no effect" (kill-criterion K1),
with no error, no warning, and a perfectly reasonable-looking table.

```python
# before: mean of [100, 110, 500, 510] = 305   <- meaningless
# after:  spacing=0.7 -> 105     spacing=2.5 -> 505
#         no spacing given, several present -> ValueError
```

The function now **refuses to guess**. Both sweep scripts were updated to
select a spacing explicitly rather than inheriting the old behaviour.

## R2 — evaluation seeds were neither held out nor unique

Two distinct bugs in one expression, `seed = self.cfg.seed + 10_000 + ep`:

**(a) Collision across runs.** Training seed 1 / episode 0 gives 10,001. So
does training seed 0 / episode 1. Runs meant to be independent were scored on
overlapping disturbance sequences, so the across-seed spread we report as
variance was partly an artefact of shared evaluation episodes — and variance is
what every confidence interval and power calculation in the charter rests on.

**(b) Selecting on the test set.** The periodic evaluation curve is what we
read to decide a run is healthy. Reporting the final number on those same
episodes scores the model on the data used to judge it.

Now three pairwise-disjoint blocks, spaced so no offset can reach the next:

```
TRAINING   seed
PERIODIC   seed*1000 + 10_000 + ep     (3 episodes,  run health)
FINAL      seed*1000 + 50_000 + ep     (10 episodes, reported)
```

Verified: 24 periodic seeds across 8 runs, 24 unique.

## R3 — `metrics.py` was imported nowhere

The same dead-code pattern as the padded critic input in round two: written,
unit-tested in isolation, and never reached by the experiment. Results still
reported unitless return.

This matters beyond tidiness. Charter §S.11 makes physical units the headline
precisely because return is **not comparable across task versions** — ours has
changed three times — and a robotics reviewer cannot judge "return 677" but can
immediately judge "RMS error 4.2 cm, min separation 0.61 m, zero collisions".

Now wired into `Trainer.evaluate()`, the learning-curve history, and the sweep
records. Live output from an untrained k3 policy:

```
RMS position error      17.10 cm
max position error      45.58 cm
min separation           0.95 m      (collision radius 0.15 m)
crashes                  1/3
downstream amplification  per-link G = 1.162, 1.068, 0.857   worst 1.789
```

G > 1 on the upstream links is the chain amplifying disturbances downstream —
the behaviour the charter predicts for a naive controller, now measurable.

## R4 — sample budget overshot

The loop collected whole rollouts unconditionally, so a budget not divisible by
`num_steps` overshot: **100,000 became 100,096**.

Small in itself, but Charter §7 requires an *identical* budget across rungs,
and the size of the overshoot depends on the rollout length — so a rung that
changed `num_steps` would silently receive a different budget. That is exactly
the class of confound the §7 rule exists to prevent. The final rollout is now
capped; the buffer was already `ptr`-aware, so partial batches were handled.

Verified: 100,000 → 100,000 exactly.

## The lesson, restated again

Round one: defects in the **physics**. Round two: correct fixes that were
**never wired in**. Round three: correct physics and correct learning, feeding
a **corrupted report**.

The progression is not coincidental. Each round moved further from where the
code crashes and closer to where it merely lies. R1 is the clearest case: it
would have produced a complete, plausible, publishable table of numbers that
answered a different question than the one we asked.

None of these four would have been caught by watching a training run.
